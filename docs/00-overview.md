# 00 — Overview

## Vision

thinkering helps adults make steady, real progress on things they want to learn — LLMs, personal finance, drawing, German, chess — in the time they actually have. It turns "I want to learn X" into a sequenced path of well-scoped goals, then generates a short interactive activity or two each day. The daily rhythm is deliberately simple: do one **Next**, one **Strengthen**, and — if it suits your fancy — a **Go further**.

It should feel enjoyable and grounding: clean and professional with creative warmth, not a health/meditation app and not a gamified streak machine.

## Canonical vocabulary

Use these terms exactly, in code and copy.

| Term             | Meaning                                                                                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Interest**     | Something the user wants to learn ("Get conversational in German"). Has a **mode** — **In focus** / **Exploring** / **Archived** — suggested at intake (D15) and freely changeable in Manage Interests as learning needs change. Created via the intake flow. |
| **Goal**         | One well-scoped unit in an interest's path — key concepts/skills teachable in one session (5 min if that's their session length; 5–10 for 10/15). Ordered.                                                                                                    |
| **Goal status**  | `not_started` → `introduced` → `strengthened` → `applied` (displayed as **"Put to use"** — see Decisions). Monotonic; each step is reached by completing an activity of that tier.                                                                            |
| **Section**      | A Today-tab lane: **Next** (introduce), **Strengthen** (consolidate), **Go further** (apply/extend).                                                                                                                                                          |
| **Activity**     | A generated multi-page interactive session targeting one goal, structured by a library item.                                                                                                                                                                  |
| **Library item** | A reusable learning strategy/template (e.g. Worked Example, Retrieval Practice, Scenario Challenge) grounded in learning science. See `06-library.md`.                                                                                                        |
| **Path**         | The ordered list of goals for an interest, plus suggestions.                                                                                                                                                                                                  |
| **Resource**     | A user-added or app-found link (article, video) usable as activity material.                                                                                                                                                                                  |
| **Reflection**   | The "Reflect on progress & update path" experience.                                                                                                                                                                                                           |
| **Intake**       | The 6-step flow that creates an interest.                                                                                                                                                                                                                     |

## Decisions log

Decisions made during planning. Change only with a doc update explaining why.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Rationale                                                                                                                                                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | The third goal state displays as **"Put to use"** (`applied` in code), replacing "Gone further". The Today section keeps the name **"Go further"** and covers two flavors: **applying** learning and **extending** it (depth, nuance, connections — see `06`). History wording comes from the library item's `outcomeLabel`: apply items say "Put to use [goal]"; extend items say what actually happened — "Went deeper on [goal]" (Dig Deeper), "Branched out from [goal]" (Connect Ideas). | "Put to use" reads naturally; extension isn't application, and expansion isn't depth — the item knows what it did, so it names the outcome.              |
| D2  | Monorepo: `apps/mobile` (Expo), `apps/web` (Next.js landing + API), shared `packages/`.                                                                                                                                                                                                                                                                                                                                                                                                       | One repo for OSS collaboration; shared types/tokens between app, API, and landing.                                                                       |
| D3  | Local store: **expo-sqlite + Drizzle ORM**, works on iOS/Android and web (wasm/OPFS).                                                                                                                                                                                                                                                                                                                                                                                                         | Typed schema + real migrations; cross-platform; local-first.                                                                                             |
| D4  | LLM calls go through a thin **Vercel API proxy** holding the Anthropic key, with per-device metering. BYO-key mode calls Anthropic directly from the client.                                                                                                                                                                                                                                                                                                                                  | Can't ship a secret in the app binary; metering requires a server anyway.                                                                                |
| D5  | Activities are **data, not code**: a versioned Activity Document JSON (Zod-validated) rendered by a native block renderer.                                                                                                                                                                                                                                                                                                                                                                    | Safety, consistency, offline replay, testability.                                                                                                        |
| D6  | Sync = **row-level last-write-wins** over `updated_at` with tombstones, plus JSON export/import. No CRDT framework (PowerSync/ElectricSQL) in v1.                                                                                                                                                                                                                                                                                                                                             | Single-user personal data; LWW is adequate and dependency-free. Export ships before sync.                                                                |
| D7  | Scheduling (what shows on Today) is **deterministic pure TS**; the LLM only generates content.                                                                                                                                                                                                                                                                                                                                                                                                | Predictable, testable, cheap.                                                                                                                            |
| D8  | Styling: **NativeWind v4** in the app + Tailwind on the landing page, sharing one token set. Fonts: **Arvo** (headings) + **Outfit** (body).                                                                                                                                                                                                                                                                                                                                                  | Shared visual language across app and web; contributor-familiar.                                                                                         |
| D9  | Analytics: PostHog, **explicit opt-in** (default off; one-time ask on the intake welcome screen, toggle in Me), anonymous random ID, event names + coarse properties only (never content, never titles). Pre-consent events (including the first intake) are **buffered locally only**; flushed to PostHog on opt-in, deleted on decline — nothing is transmitted before consent.                                                                                                             | Users control their data — the local-first promise extends to telemetry — while a willing user's first-session data isn't lost to the timing of the ask. |
| D10 | Usage metering identity: server-issued **device token** (id + HMAC secret in SecureStore) with daily budgets; iOS App Attest as later hardening.                                                                                                                                                                                                                                                                                                                                              | Simple, cross-platform, good-enough abuse resistance at launch scale.                                                                                    |
| D11 | Models: **Sonnet** (latest) for path/activity generation, **Haiku** for small fast calls (cards metadata, resource descriptions, suggestions). Prompt caching on the shared system preamble.                                                                                                                                                                                                                                                                                                  | Quality where pedagogy matters, speed and cost control elsewhere.                                                                                        |
| D12 | Day boundary = device-local midnight. "Completed today" counts reset then.                                                                                                                                                                                                                                                                                                                                                                                                                    | Matches user intuition; no server clock needed.                                                                                                          |
| D13 | License is **AGPL-3.0** — intentional.                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Confirmed by Reb.                                                                                                                                        |
| D14 | Beta usage cap: **~60 generations per device per day**, with reserved headroom so in-activity calls (review page, Ask) never starve. Tune with real data.                                                                                                                                                                                                                                                                                                                                     | Generous while testing; the meter UI makes changes painless later.                                                                                       |
| D15 | Interest **mode is suggested at intake**: daily / several-times-a-week frequency or career / personal-goal motivation → **In focus**; for-fun + when-I-can → **Exploring**. Shown subtly on the final intake step, one tap to change; movable anytime in Manage Interests.                                                                                                                                                                                                                    | Placement follows commitment; the user stays in control.                                                                                                 |
| D16 | **Concepts and skills are first-class**: goals carry structured concept/skill items; activities declare which they target; Path shows them under an expanded goal with coverage indicators.                                                                                                                                                                                                                                                                                                   | Helps users see and process what's inside a goal; enables per-concept highlighting in activities.                                                        |
| D17 | **Schema compatibility policy**: additive-first migrations, versioned ActivityDoc/export payloads, sync gated on a minimum schema version. See `02`.                                                                                                                                                                                                                                                                                                                                          | Old builds must never corrupt or misread data.                                                                                                           |
| D18 | **Activity quality review**: aggregate ratings flow through PostHog (opt-in); content-level review only via an explicit per-activity "share with the developers" action.                                                                                                                                                                                                                                                                                                                      | Lets us inspect quality without ambient content collection.                                                                                              |
| D19 | Supabase: **fresh project**, email/password auth only for v1; v1 sync is **backup/restore semantics** (not live multi-device). Landing + API on Vercel under Reb's `thinkering.app` domain.                                                                                                                                                                                                                                                                                                   | Confirmed by Reb.                                                                                                                                        |
| D20 | **Test strategy is tiered and explicit** (`10-testing.md`): `pnpm verify` is the gate; effort concentrates in `packages/core` and the migration chain; the LLM boundary is tested against recorded fixtures and a malformed-output corpus, never live calls; UI beyond the activity renderer is deliberately untested. A **fixture AI mode** runs the whole app deterministically at zero token cost.                                                                                         | Fast, honest feedback on the surfaces where mistakes are expensive, without a slow suite that agent sessions will grow unchecked.                        |
| D21 | **Feedback has two explicit channels**: community feedback opens a public Featurebase portal; private feedback and activity quality reports go through signed Resend-backed routes. Only coarse app context is attached automatically, and content never enters analytics.                                                                                                                                                                                                                    | Users can choose public discussion or a private message without weakening the local-first promise.                                                       |
| D22 | **Session replay is a separate opt-in**, default off, asked as the second step of the one-time ask with both answers weighted the same: its copy says plainly that recordings show your activities and what you type. Recordings carry the same anonymous id; email, password and API key fields are masked.                                                                                                                                                                                  | Watching real sessions is the fastest way to see what's confusing, and some learners are happy to help — but only by a choice that names what it shows.  |
